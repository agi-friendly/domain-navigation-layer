# workflow - work lifecycle portal

This directory defines how work moves through the repository over time.
The core idea is to separate active work, promoted knowledge, archive material, and repository history.

## What this portal covers

- How to treat a `future` working area
- When to promote repeatable knowledge into DNL
- When to move raw work bundles into archive storage
- How to keep repository history separate from working notes

## Quick entry points

- Definitions and roles: `@concepts.md`
- Rules for writing future notes: `@future-authoring-rule.md`
- Promote repeatable material into DNL: `@future-to-dnl.md`
- Move raw bundles into archive storage: `@future-to-archive.md`
- Record repository-level history: `@repo-history-guide.md`

## Core principles

1. `future` is an active work area, not a trash bin.
2. DNL holds reusable, stable knowledge.
3. Raw work bundles should not stay in active portals forever.
4. Repository history and archived bundles are not the same thing.
5. Keep the current repository's operating history separate from its public docs.

## Lifecycle summary

```text
future
  -> promote reusable knowledge into DNL
  -> move raw bundles into archive storage
  -> keep repository history as a separate narrative
```

## When to read this portal first

- When you are deciding where a working note belongs
- When you need to decide whether to promote a note into DNL
- When you are unsure whether something belongs in archive or history
- When a prompt mentions future work, archiving, or lifecycle rules

## One-line summary

Keep active work, promoted knowledge, archive bundles, and repository history separate.
