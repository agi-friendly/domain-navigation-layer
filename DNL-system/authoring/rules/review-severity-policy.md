# Review Severity Policy

DNL QA 봇 및 사람이 문서를 리뷰할 때, 아래 심각도 기준으로 이슈를 분류합니다.

## [BLOCKER]
- 보안/민감정보 리스크
  - 내부 URL, 계정/토큰, 고객사 정보, 실서버/내부망 IP, 로그 원문 등 노출 가능성
- 네비게이션(진입점) 파괴
  - README/포털이 없어서 들어갈 수 없거나, "어디로 가야 하는지" 안내가 깨진 경우
- 정본 링크 정책 위반
  - `## HUMAN_LINKS` 섹션, `- [HUMAN_LINK]` 라인, 로컬 markdown 파일/폴더 링크 사용
  - 예외는 이미지 링크, 외부 웹 URL, fenced code block 내부 규칙 예시뿐
- 링크 깨짐 / 경로 규칙 위반(치명)
  - 링크가 실제로 404/ENOENT
  - `../../` 등 규칙 위반으로 구조 변경 시 대량 파손이 확실한 링크 패턴
- 상위 권위 문서와의 명시적 충돌
  - company → product → project 권위 규칙(multi-dnl-authority) 위반

## [WARN]
- 최신성/정합성 리스크
  - 날짜/버전/대상 환경이 불명확해서 잘못 적용될 수 있는 내용
  - 같은 개념이 여러 문서에서 표현이 달라 혼동을 유발
- 암묵 가정
  - "당연히 ~일 것이다" 형태로 환경/권한/구성 가정이 숨어있는 경우
- 링크는 살아있지만 위험한 링크 패턴
  - 깊은 상대경로, 디렉토리 이동에 취약한 구조, 포털을 우회하는 링크 등

## [IDEA]
- 구조/토큰 효율 개선
  - 더 적은 문서/토큰으로 목적을 달성하도록 재구성 가능
- 템플릿/예시/요청 유형별 진입 가이드 추가
- 문서 분할/병합 제안
  - 중복을 줄이거나(또는 의도된 중복임을 명시) 읽기 경로를 단순화

---

### 메모
- 심각도가 애매하면 일단 WARN으로 두고, "왜 위험한지"를 한 줄로 설명합니다.
- 검증할 수 없는 주장/정보는 **UNVERIFIED**로 표시하고 질문으로 마무리합니다.
